# Contributing

1. Fork the repository and create a branch from `main`.
2. Run `npm install`, then `npm run dev`.
3. Before opening a PR: `npm run typecheck && npm run lint && npm test && npm run build && npm run test:e2e`. Install Chromium once with `npx playwright install chromium`. To match GitHub Pages, build and run E2E with `BASE_PATH=/layout-forge/`.
4. Code style: TypeScript, no code comments, shadcn/ui components. Register new tools in `src/lib/tool-catalog.ts` and connect their view/icon in `src/components/tools/tools-view.tsx`.
5. Describe what changed and how to verify it in the PR; attach a screenshot for UI changes.

Ideas go to [Discussions](https://github.com/vumox/layout-forge/discussions); reproducible bugs go to Issues. Read [ROADMAP.md](ROADMAP.md) before proposing a large feature.

## Media and SEO

- Run `npm run generate:icons` to rebuild the PWA PNG icons.
- Build and start preview with `BASE_PATH=/layout-forge/ npm run build` and `BASE_PATH=/layout-forge/ npm run preview -- --host 127.0.0.1`.
- In another terminal, run `npm run record:demos`. It needs Chromium and `ffmpeg`; set `DEMO_URL` for a different preview URL. GIFs are saved in `docs/demos/`.
- SEO guides are generated by `scripts/seo.ts` during the Vite build. Update its canonical origin and `index.html` when deploying to a different public domain. Verify the generated HTML and links with E2E tests.
- GitHub project Pages publishes `robots.txt` inside `/layout-forge/`. Crawlers apply robots rules from the domain root, so a custom domain or control of the root site is needed for an authoritative robots policy. The generated sitemap can still be submitted directly to search engines.
- Use `usePersistent` for generator settings so Copy link captures the current value. Keep uploaded files out of serializable settings; shared links only carry configuration.
